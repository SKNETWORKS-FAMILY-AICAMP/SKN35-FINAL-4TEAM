# 데이터 전처리 결과서

- 프로젝트: SlotAgent
- 작성 역할: ② 평가팩 및 채점 담당
- 작성일: 2026-11-25
- 전처리 버전: 1.0
- 작업 범위: 11/18 사전 실험 JSONL의 정제, 특징 추출, 학습용·최종 평가용 CSV 생성 및 검증
- 현재 상태: 전처리·자동 검증·3개 모델 교차검증 비교·LightGBM 선정 및 저장·최종 평가1회 완료(2026-11-25). 자동 오답50·정답50 표본의 사람 검수100건 및 결과 반영 완료(2026-11-27, 박민하). 학습표·모델은 변경하지 않음

실행 기록을 보고 오답 위험이 높은 답변을 우선 검토하는 보조 모델의 학습 데이터를 준비했다. 원본 1,656건 중 지정된 도구 범위 밖 기록 108건을 제외하고 1,548건을 처리했다. 결과는 학습용 1,080건과 최종 평가용 468건으로 분리했다. 이 모델은 SlotAgent의 채택·기각 판정에 사용하지 않는다.

## 2. 정제

### 이유별 처리 전후 건수

| 단계 | 이유와 처리 방식 | 전 | 제외 | 후 |
|---|---|---:|---:|---:|
| 입력 구조 검사 | JSON 파싱, 필수 필드, 자료형, 숫자 유효성, 실행 ID 중복 등을 검사. 오류가 있으면 임의 제거하지 않고 중단 | 1,656 | 0 | 1,656 |
| 도구 범위 밖 제외 | `cand == "A_own"`이면서 `scope_a == false`인 기록만 제외 | 1,656 | 108 | 1,548 |
| 특징 추출 | 남은 모든 기록에서 특징 10개 계산. 일부 특징의 결측 때문에 행을 제거하지 않음 | 1,548 | 0 | 1,548 |
| 유형 단위 분할 | 학습용과 최종 평가용으로 분리. 행 추가·삭제 없음 | 1,548 | 0 | 학습 1,080 + 최종 평가 468 |

제외 조건은 두 조건의 **AND**이다. `A_own` 기록 전체나 `scope_a=false` 기록 전체를 일괄 제외한 것이 아니다. 제외된 108건은 원본 자동 채점 라벨상 모두 오답이었다. 제공자가 지정한 ML 학습 범위에 따라 제외했으며, 프로젝트의 공식 평가에서 도구 범위 밖 문항을 실패로 세는 정책을 변경한 것은 아니다.

### 결측 및 잘린 응답 처리

도구 결과 문자열은 최대 600자까지 저장된 원본이다. 각 도구 단계의 `result_chars`와 저장된 `result`의 길이를 비교하여, 실제 길이가 저장 길이보다 큰 경우를 잘림으로 판정했다. 정확히 600자라는 이유만으로 잘림으로 단정하지 않았다.

| `grounded_ratio` 결측 사유 | 기록 수 | 처리 |
|---|---:|---|
| 한 개 이상의 도구 결과가 잘림 | 823 | 실제 결과 전체를 확인할 수 없으므로 빈칸 |
| 잘림은 없지만 최종 답에서 비교 대상 값을 추출하지 못함 | 209 | 근거 비율의 분모를 구성할 수 없어 빈칸 |
| 합계 | **1,032** | 전체 1,548건 중 **66.67%** |

두 사유는 중복 없이 집계했다. 나머지 516건은 비율을 계산했다. **결측과 0은 구분했다.** 비교할 답 값은 있지만 도구 결과에서 하나도 발견되지 않은 경우만 비율 0이며, 자료 부족으로 계산할 수 없는 경우는 결측이다.

| 특징 | 학습용 결측 | 최종 평가용 결측 | 전체 결측 |
|---|---:|---:|---:|
| `grounded_ratio` | 639 / 1,080건, 59.17% | 393 / 468건, 83.97% | 1,032건 |
| 나머지 특징 9개 | 0 | 0 | 0 |

전처리 단계에서는 결측을 0이나 전체 평균으로 채우지 않았다. 이후 학습 단계에서 기존 학습 코드의 로지스틱 회귀는 학습 폴드 안에서 중앙값 대체·결측 표시·표준화를 수행했고, LightGBM은 결측을 직접 처리했다. 학습 설정과 결과는 [학습결과서](학습결과서.md)에 기록했다.

## 3. 라벨

### 라벨 생성 방법

원본의 불리언 `correct`를 그대로 이용하여 다음과 같이 이진 라벨을 생성했다.

```python
is_wrong = 1 if correct is False else 0
```

`correct`가 문자열이나 숫자인 경우를 임의로 참·거짓으로 변환하지 않고 입력 오류로 처리한다. 이번 작업에서는 문항 정답을 다시 계산하거나 원본 라벨을 변경하지 않았다.

| 구분 | 오답 라벨 1 | 정답 라벨 0 | 합계 | 오답 비율 |
|---|---:|---:|---:|---:|
| 학습용 | 226 | 854 | 1,080 | 20.93% |
| 최종 평가용 | 56 | 412 | 468 | 11.97% |
| 전체 전처리 대상 | **282** | **1,266** | **1,548** | **18.22%** |

제공자 안내에 따르면 `correct`는 글자 포함 여부를 이용한 자동 채점 결과다. 따라서 이 표의 정답·오답은 **원본 자동 채점 라벨 기준**이며 사람이 확인한 의미적 정답 여부와 동일하다고 보장하지 않는다. 업무 전체 성공, 금지 행동 여부, 최종 답의 사실성을 새로운 하나의 기준으로 합쳐 재정의하지 않았다.

### 사람 확인 현황

## 4. 특징

`config.py`의 기존 특징 10개와 순서를 유지했다. 특징 함수는 실행 단계·도구 응답·최종 답·토큰 수만 읽고, 라벨과 문항·후보·설정의 관리 정보를 읽지 않도록 분리했다.

| 이름 | 뜻 | 계산 방법 | 빈 값 처리 |
|---|---|---|---|
| `n_tool_calls` | 도구 호출 수 | `steps`에서 `type="tool"`인 단계 수 | 호출이 없으면 0 |
| `n_tool_errors` | 오류가 기록된 단계 수 | `steps`에서 `error` 값이 존재하고 비어 있지 않은 단계 수 | 오류가 없으면 0 |
| `n_empty_results` | 빈 결과 목록을 받은 호출 수 | 루트 빈 배열 또는 지정된 루트 목록 필드가 비어 있는지 확인. 잘린 JSON은 제한된 문자열 접두부로 판정 | 빈 목록이 없으면 0. 오류 객체를 빈 결과로 세지 않음 |
| `n_repeat_calls` | 같은 도구·인자의 추가 호출 수 | `(name, 정규화한 args)`의 전체 개수에서 고유 개수를 뺌. 객체 키 순서는 무시하고 배열 순서는 유지 | 반복이 없으면 0 |
| `in_tokens` | 입력 토큰 수 | 원본 `in_tokens` 사용 | 필수값. 없거나 음수·잘못된 자료형이면 중단 |
| `out_tokens` | 출력 토큰 수 | 원본 `out_tokens` 사용 | 필수값. 없거나 음수·잘못된 자료형이면 중단 |
| `answer_len` | 최종 답 길이 | 원본 `final` 문자열의 문자 수 | 빈 문자열이면 0 |
| `says_none` | 없다는 표현의 존재 여부 | `없습니다`, `없어요`, `존재하지 않` 등 정규식과 일치하면 1, 아니면 0 | 필수 문자열에서 계산하므로 결측 없음 |
| `asks_back` | 되묻는 표현의 존재 여부 | `알려 주실`, `추가 정보 … 필요`, `please clarify` 등 정규식과 일치하면 1, 아니면 0 | 필수 문자열에서 계산하므로 결측 없음 |
| `grounded_ratio` | 최종 답 값의 도구 결과 내 출현 비율 | 답에서 추출한 고유한 번호·시각·버전 값 중 도구 결과에서도 발견된 값의 비율 | 도구 결과가 하나라도 잘렸거나 답에서 값을 추출하지 못하면 빈칸 |

### 특징 계산의 구체적 기준

빈 목록은 루트 `[]` 및 `items`, `workflow_runs`, `issues`, `pull_requests`, `releases`, `tags`, `jobs`의 루트 목록을 대상으로 한다. `{"error":"Not Found"}`를 빈 목록으로 취급하지 않는다. JSON 파싱이 불가능한 경우에는 루트 목록의 접두부만 제한적으로 확인한다.

근거 비율의 값 추출은 다음 범위로 제한했다.

- 번호: `#숫자`, `숫자번`, 독립된 3자리 이상 정수.
- 시각: `HH:MM` 또는 `H시 MM분`을 분 단위 `HH:MM`으로 정규화.
- 버전: `v2.1.0`처럼 3부분으로 구성된 버전. 접두사 `v`와 대소문자를 정규화.
- 날짜·버전·시각·커밋 해시 내부 숫자를 별도의 번호로 중복 계산하지 않음.
- 같은 값이 답에 여러 번 등장해도 고유한 `(값 종류, 정규화된 값)` 기준으로 한 번만 계산.

```text
grounded_ratio
= 도구 결과에서도 발견된 답의 고유 값 수 / 답에서 추출한 고유 값 수
```

이 비율은 값의 출현만 확인한다. 도구 결과의 숫자가 실제 질문의 대상과 연결되는지, 최종 답이 그 값을 올바르게 해석했는지까지 검증하지 않는다. 표현 특징도 정규식 기반 신호이며 부정·인용·문맥을 이해하는 의미 판정기가 아니다. 실제 정규식은 코드와 요약 JSON에 기록했다.

제공자가 지정한 유형 목록을 그대로 적용했으며, 결과를 보고 유리한 유형을 골라 나누지 않았다.

## 6. 한계

1. **데이터 규모와 실험 범위:** 기록은 1,548건이지만 서로 독립된 문항 1,548개가 아니다. 문항 46개·유형 11개의 반복 실행이며 모델도 GPT-4.1-mini 1종이다. 실제 운영 환경이나 다른 모델에 대한 일반화는 아직 확인하지 않았다.
2. **자동 라벨:** 학습표는 `correct`를 그대로 변환한 자동 라벨을 유지한다. 11/27 별도100건 사람 감사에서1건의 자동 정답 오류(R064)를 확인했으며 전체1,548건을 사람 라벨로 교체한 것은 아니다.
3. **도구 결과 잘림과 결측:** 기록823건에 잘린 응답이 있으며, 추출 가능한 답 값이 없는 경우까지 포함해 grounded_ratio의 결측은 전체66.67%다. 학습·최종 평가의 결측 비율도 다르므로 모델이 이 차이에 의존하는지 학습 후 점검해야 한다.
4. **근거 비율의 범위:** 번호·분 단위 시각·3부분 버전의 출현만 비교한다. 제목·원인 설명·커밋 해시의 의미, 값 사이 관계, 부정·모순·인용 여부는 판단하지 않는다.
5. **정규식 표현 특징:** `says_none`와 `asks_back`은 표현 탐지 규칙이다. 다른 표현을 놓치거나 인용 문장을 잘못 탐지할 수 있어 학습용 표본과 원문의 직접 대조가 필요하다.
6. **범위 밖 실패 제외:** A_own 범위 밖108건을 제외한 집합에 대한 결과다. 향후 모델 성능을 전체 실험 기록이나 모든 도구 범위에 그대로 적용한다고 설명하지 않는다.
7. **내용 중복 검사의 한계:** 실행·문항·유형 ID의 겹침은 검사했지만, ID가 달라도 실질적으로 유사한 문항이 다른 유형에 남아 있을 가능성까지 자동으로 제거한 것은 아니다.
8. **완료 범위:** 전처리·자동 검증·모델 학습·교차검증 성능 비교를 완료하고 PR-AUC 기준으로 LightGBM을 선정·저장했다. 고정 모델로 최종 평가를1회 완료했으며 11/27 사전 실험 표본100건 사람 검수와 결과 반영을 완료했다. 제품 판정기 검증과 재학습은 수행하지 않았다.
